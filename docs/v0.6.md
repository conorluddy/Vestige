# V0.6 — Memory lifecycle

Memories can be revised, superseded, and explicitly reviewed while retaining
their journal history. Hybrid recall is the default; usage counters contribute
to ranking and context-pack ordering.

## Revise and supersede

```bash
vestige revise mem_<ID> "Updated body" --json
vestige decision add "Replacement decision" --supersedes mem_<OLD_ID> --json
vestige why mem_<OLD_ID> --json
```

Revision keeps the handle and journals the prior body. Supersession soft-deletes
the old memory and links it to its replacement. `vestige restore` can reactivate
the old memory and clears its supersession link.

## Review queue

```bash
vestige review
vestige review --min-age-days 60 --importance-ceiling 0.4 --json
```

Listing is non-mutating: it does not increment usage counters or write traces.
The default predicate is active, older than 30 days, importance strictly below
0.5, and both recall and expand counts equal to zero. Decisions and project
summaries are always excluded. Results are ordered by creation time, oldest
first, with ID as a deterministic tie-breaker.

JSON listing returns an array with `id`, `type`, `importance`, `recall_count`,
`expand_count`, `age_days`, and `one_liner` for each entry. Age is whole elapsed
days; eligibility compares the full elapsed age, so a memory just over 30 days
old is eligible even though its displayed age is 30.

## Explicit batch forgetting

```bash
vestige review --forget mem_<FIRST_ID>,mem_<SECOND_ID> --json
vestige restore mem_<FIRST_ID> --json
```

Only the explicitly selected IDs are changed. Selection is not restricted to
the queue heuristic, but every ID must belong to the current project. JSON
returns an array of `{id, status, message?}` outcomes: `deleted`,
`already_deleted`, `not_found`, `out_of_scope`, or `error`. Already-deleted IDs
are a successful no-op. Invalid IDs and store failures report `error` with a
message. Each ID is processed independently; a failed ID does not abort later
IDs. Any failure returns a nonzero exit code after printing the full report.

Forgetting appends journal events and sets `deleted_at`; it never hard-deletes
a memory. Forgotten memories disappear from subsequent review listings.
